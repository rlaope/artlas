# Atlas DELTARUNE reel

Make a readable character moment using DELTARUNE's own pixel language. Keep native actors, generated extensions, procedural staging and source music distinguishable in the production record. A small sprite needs accurate acting and composition; enlarging an anime drawing or fitting every pose to the same bbox does not supply them.

The latest request controls characters, chapter/world, tone, actions, text, duration, cadence and music. Queen's grief, a dead partner, torn SOULs, cold lighting and an absence of tears are conditional scene choices, not defaults for every DELTARUNE reel. Infer routine asset and timing choices and carry out requested edits; ask only for a material unresolved choice. Do not impose a new candidate-approval gate on an already clear request.

## Work from the story to the native frame

1. **Write the literal beats.** Record who looks at whom, what each hand does, who responds, props and their scale, explicit stillness, text policy and music cue. Give each requested beat an observable phone-size condition. Retain an accepted source ID/hash when revising a scene.
2. **Inspect actual game sources.** Read [native assets and staging](references/native-assets-stage.md) for the pinned source study, useful asset candidates, `.yy` ordering/origins and Dark Fountain draw logic. Preserve original PNGs and label third-party decompilation honestly. Confirm the visible pose and object role rather than trusting a filename.
3. **Author only the missing action.** Show native references to the image model and generate a coherent action family. Use deterministic sprite processing with shared scale, sampling phase and anchors. Review the whole actor and head attachment before local face details; do not paint replacement characters or corrective facial features in code.
4. **Compose and time the scene.** Keep one native grid, integer placements and final nearest-neighbour enlargement. Port required game effects from their draw stack. Separate actor pose cadence from export FPS and preserve requested static actors/props through compositing. Review each story beat, prop silhouette and contact shadow at native and phone size.
5. **Build configurable sound.** Read [audio, verification and delivery](references/audio-delivery.md) for source-window timing, optional slower playback, independent music/effect stems and final-file checks. Use the requested song and space; report an unofficial cover as a cover. Do not label a measurement-only mix as heard.
6. **Review the exact movie, then deliver.** Have a separate reviewer inspect actual decoded transitions and playback for story, identity, scale, grounding, prop meaning, temporal stability and sound. Fix the identified issue within scope and rerender the affected window before a full master. A still, component count, source hash or unique-frame count alone cannot approve the result.

## Keep the requested boundaries

- **Text:** no added titles, labels or lyrics by default. Physical text is conditional on the current request and must fit its actual surface without changing character geometry. A later removal instruction overrides earlier permission.
- **Scope:** diagnostic-only or skill-only work uses isolated proof paths and before/after production hashes. Set output/QA paths before renderer initialization; leave current sources, exports and library copies untouched. Do not sync a vendored skill or claim the current video repaired in this mode.
- **Delivery:** one canonical Atlas MP4, with no duplicated normal/shorts pair or unrequested title wrapper. Library and dashboard copies preserve those bytes. Additional formats need an explicit request. Retain reproducible sources and complete verification/playback before retiring only this work's obsolete versions under the user's authorized cleanup rules.
